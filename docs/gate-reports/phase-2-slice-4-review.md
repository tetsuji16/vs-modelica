# Adversarial review — phase 2 slice 4 (diagram webview)

Date: 2026-08-02
Reviewer: adversarial pass over the slice-4 commit `84082b5`
Outcome: **5 defects found and fixed**, 2 of them user-visible in real VS Code
despite the slice shipping with 169 green tests.

## Why the green suite proved nothing

The slice was verified in a browser harness that **inlined `diagramStylesheet()`
into a hand-written page**. The extension does not do that: it links
`media/diagram.css` and serves `buildDiagramHtml()`'s markup. Two different
artefacts. Every layout claim in the slice-4 gate report was made about a page no
user will ever load.

The rule this cost us: _verify the artefact that ships, assembled the way it
ships._ The harness is now generated by `apps/vscode/tools/make-harness.mjs`,
which calls the real `buildDiagramHtml()` and links the real `media/diagram.css`,
so it can only drift from production by the CSP meta tag it has to drop for
`file://`.

## Defects

### 1. The shipped stylesheet was stale — every rule this slice added was missing

`media/diagram.css` was a hand-maintained checked-in file. `diagramStylesheet()`
was the thing tests asserted on, and `DIAGRAM_STYLESHEET` was exported but
written nowhere. Measured, not inferred:

```text
on-disk bytes: 1612  generated bytes: 1597  identical: false
.mso-stage       -> on disk: false | generated: true
.mso-zoom        -> on disk: false | generated: true
transform-origin -> on disk: false | generated: true
```

In real VS Code the stage would have had no `position: absolute` and no
`transform-origin: 0 0`, so pan and cursor-anchored zoom would both have been
wrong — the exact features the slice was about.

Fix: `tools/build-webview.mjs` now generates `media/diagram.css` from
`diagramStylesheet()` alongside the JS bundle. Test: _ships the stylesheet the
code generates_. Verified to have teeth by deleting `transform-origin` from the
built file — the test fails, and passes again after a rebuild.

### 2. Fit measured a 200px viewport, because the sheet never got a height

Only visible once the harness used the real CSS. `.mso-sheet` asked for
`height: 100%` while `html`, `body` and `.mso-canvas-shell` had no height at all,
so the percentage did not resolve and the sheet collapsed to its `min-height`:

```text
sheet: [1264, 200]   zoom: 23%   stage: translate(526.4px, 12px) scale(0.2347)
```

The viewport math was right; it was correctly fitting a diagram into a 200-pixel
strip at the top of an empty panel. Fix: a resolvable height chain
(`html, body { height: 100% }`, flex `.mso-canvas-shell`, `.mso-sheet-area` with
`min-height: 0`, `.mso-sheet { flex: 1 }`). After the fix, same measurement:

```text
sheet: [932, 544]    zoom: 64%   stage: translate(178.776px, 32.64px) scale(0.6383)
```

Test: _gives the sheet a resolvable full-height chain_.

### 3. The "second lock" on SVG did not lock

The client's comment claimed adopting via `DOMParser` meant "no script can
execute". It removed `<script>` and nothing else. Also passing through:
`onload=` / `onclick=` on any element (script by another name), `<foreignObject>`
(arbitrary embedded HTML), `href="javascript:…"`, and
`<image href="https://…">` — an outbound request that is a tracking pixel and
breaks the webview's offline behaviour. The nonce CSP does block inline handlers,
so this was defence-in-depth that wasn't there, plus a comment that lied.

Fix: `src/webview/client/sanitise.ts`, in its own module so it can be tested
against a real DOM (`jsdom`, 6 tests) instead of asserted by inspection. It drops
forbidden elements at any depth, every `on*` attribute, and any URL attribute
that is not a `#fragment` or a `data:image/` URI — with control characters
stripped first, so `java&#10;script:` does not slip through.

### 4. A malformed message froze the canvas silently

The client checked `type` and `version`, then read `message.payload.svg`. A
message with no payload threw a `TypeError` inside the listener, which nothing
catches — the canvas stops updating with no error shown. `isWebviewReady` on the
host was weaker still: it checked `type` but not `version`, so a v2 client could
hand a v1 host a handshake it should have rejected.

Fix: `isDiagramMessage` validates every field the client dereferences;
`isWebviewReady` now requires the version. 3 tests, including the malformed
payload that used to throw.

_(Found while writing those tests: my first version of the rejection case was
`{ version: 2, ...scene }`, which spreads `version: 1` straight back over the 2.
The test failed for the right reason — the value really was valid. Test bug, not
a code bug, and a reminder that a red test is a claim to check, not a verdict.)_

### 5. A save burst queued one compiler round trip per save

`pending = pending.then(...)` serialises but does not coalesce. Auto-save on a
large model queues N renders, N−1 of which are thrown away after paying full
compiler cost. Fix: a `running`/`queued` pair collapses any number of requests
arriving during a render into exactly one follow-up.

## Verification

```text
pnpm -r check   -> tsc --noEmit clean across 5 projects
pnpm -r build   -> bundle + stylesheet generated
pnpm vitest run -> 28 files, 182 tests, all passing (was 169)
```

Browser, against the generated shell and the generated stylesheet: sheet
932×544, whole circuit visible and centred at 64%.

## What was checked and found sound

- Path handling: `samePath` normalises separators and case, which is right for
  Windows and OMC's forward slashes; no path is passed to a shell.
- `findClassesInFile` recursion is depth-bounded (`MAX_DEPTH = 4`) and a
  `getSourceFile` failure skips one class rather than aborting the walk.
- The webview cannot reach the filesystem: `localResourceRoots` is `media/` only,
  and it never receives source text — only rendered SVG.
- HTML escaping of the document title (already covered by an existing test).
- `fitViewport` returns identity for degenerate input rather than an infinite
  scale, so a zero-area or unlaid-out sheet cannot produce `NaN` transforms.

## Still open (not defects, but known gaps)

- No pixel baselines for the webview itself; correctness is asserted on
  measurements and on the composed-SVG baselines, not on rendered pixels.
- `ctrl`+wheel is consumed for zoom, which shadows VS Code's own font zoom in
  the panel. Deliberate for now; revisit if it annoys.
- Error text from the compiler is shown verbatim in the status row and can
  contain absolute paths.
